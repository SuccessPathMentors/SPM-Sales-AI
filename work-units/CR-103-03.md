# CR-103-03 — Memory-safe target-family selective STAGING reads

Status: IMPLEMENTED_FOR_REVIEW
Issue: #37
Parent: WU-103 / #30

## Runtime trigger
WU-103 STAGING manual execution crashed with an n8n out-of-memory error at `Load SERVICES [WU103 READ ONLY]` after earlier canonical family reads had completed. The failing graph sequentially loaded multiple complete KB families in one execution.

## Root cause
The publisher did not need all canonical KB families. A WU-103 change candidate has one explicit `target_family`, but the original STAGING graph loaded FAQ, SUBJECTS, SUBJECT_PATHWAYS, SERVICES, LOCATIONS, FALLBACKS, PACKAGES and POLICIES sequentially before making the final decision. Execution data and Google Sheets results accumulated in memory.

## Frozen correction
V1 manual publication processes at most one RELEASE_APPROVED, not-yet-PUBLISHED candidate per execution.

Path:
`Ledger → Early Preflight → exact-record Shadow read → target-family routing → ONE exact-ID canonical read → Publish Decision`

Rules:
- zero eligible candidates → no-op / blocked result;
- more than one eligible candidate → `MULTIPLE_RELEASE_APPROVED_CANDIDATES_V1` and no deep reads;
- unknown family / invalid type / missing update ID → blocked before deep reads;
- shadow read filters by the candidate logical record ID;
- canonical read filters by the exact family-specific ID field;
- at most one of the eight canonical family read nodes executes;
- decision code treats unexecuted family nodes as empty;
- duplicate candidate-key detection still evaluates the full ledger;
- all existing human approval, regression-payload hash binding, business-truth, stale-base, lineage, retry-recovery and STAGING-only gates remain unchanged;
- writes remain fail-closed and limited to WU103_CHANGE_LEDGER_STAGING and WU103_KB_SHADOW_STAGING;
- Production workflow and canonical KB writes remain denied.

## Acceptance evidence required
- static graph proves max one canonical family read per run;
- exact shadow/canonical lookup filters verified;
- contract/core tests remain green;
- deterministic candidate SHA locked;
- remote readback verifies inactive STAGING graph;
- rerun the FALLBACKS fixture that previously crashed and confirm SERVICES/PACKAGES/POLICIES are not executed;
- canonical Production KB unchanged.
