# WU-105 — Golden Intents Optimization

Status: READY_FOR_REVIEW
Version: 0.1
Issue: #60

## Objective
Improve the accuracy, answer quality, next-step quality, and conversion usefulness of a bounded set of high-value/high-risk existing intents (the **Golden Intents**) without changing the locked 62-intent taxonomy, business truth, action permissions, or Production directly.

## Why this unit exists
WU-104 hardened short-query and ambiguity behavior. WU-105 now targets the most important existing intent journeys so that the agent is not merely classifying correctly, but answering directly, preserving context, asking the smallest useful next question, and moving the customer toward the correct safe next step.

This is an optimization unit, not a taxonomy redesign.

## Golden-set selection contract
WU-105 must publish a versioned Golden Intent manifest selected only from the existing 62 intents.

An intent qualifies when one or more of the following is true:
1. high customer frequency in WU-101 analytics;
2. high business/conversion value;
3. high confusion/re-ask/drop-off signal;
4. high source-truth or action risk;
5. common entry point to trial/registration/support resolution.

The manifest must be bounded for V1 (target: 8–15 intents) and must record the selection reason for every included intent.

WU-105 must not silently optimize all 62 intents.

## Optimization contract
For each Golden Intent, define and test:
- direct answer requirement;
- allowed authoritative source(s);
- minimum context needed before asking a question;
- fields that must not be re-asked when already known;
- preferred next-best-action;
- stop/override conditions;
- forbidden unsupported claims/actions;
- EN/AR/FR semantic parity requirement;
- compatibility with WU-104 short-query/clarification behavior.

## Response quality rules
A Golden Intent response must follow this order unless a locked safety/support rule overrides it:
1. answer the user's current question first;
2. reuse trusted known context;
3. do not repeat information unnecessarily;
4. ask at most one smallest relevant missing qualifier when needed;
5. present one clear next step when useful;
6. do not manufacture urgency, guarantees, discounts, availability, credentials, policy outcomes, or action success.

## In scope
- selecting and freezing the V1 Golden Intent manifest;
- intent-specific answer/NBA optimization for that bounded set;
- confusion-pair tests between selected intents and their nearest existing neighbors;
- no-reask and context-continuity tests;
- direct-answer-before-qualification behavior;
- EN/AR/FR semantic parity for the Golden set;
- compatibility with WU-104 ambiguity handling;
- deterministic telemetry labels for Golden-set evaluation;
- inactive STAGING candidate and runtime matrix;
- regression against non-Golden intents and locked upstream controls.

## Out of scope
- adding/removing/renaming intents;
- classifier replacement or second classifier LLM;
- broad dialect expansion (WU-106);
- live human handoff adapter (WU-107);
- WhatsApp staff notification (WU-108);
- KPI dashboard implementation (WU-109);
- global optimization of all intents (WU-110 regression/optimization pack remains downstream);
- pricing/policy/source-truth changes;
- new external side effects or new business-action permissions;
- direct Production activation.

## Safety / hard stops
- changing the intent taxonomy;
- optimizing an intent using invented business truth;
- changing prices/policies/availability/teacher claims without an authoritative source;
- allowing optimization to authorize an irreversible action;
- stale context overriding a clear current request;
- re-asking trusted known fields merely to follow a script;
- using out-of-scope as a generic low-confidence bucket;
- bypassing WU-104 clarification safeguards;
- adding a second LLM classifier/reviewer layer;
- modifying/activating Production directly.
