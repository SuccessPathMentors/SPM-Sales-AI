# WU-103 Runtime Hardening 001 — Early Preflight Short-Circuit

Status: IMPLEMENTATION HARDENING

## Problem
The first controlled WU-103 runtime fixture is intentionally non-publishable (`regression_status=FAIL`). The current STAGING maintenance workflow reads the ledger, shadow history, and all eight canonical KB families before evaluating that deterministic blocking condition. This is safe but unnecessarily slow and can make a blocked manual execution appear to wait.

## Correction
Insert a deterministic preflight stage immediately after `Load WU103 Change Ledger [STAGING]`.

The preflight evaluates only ledger-local gates that require no shadow/canonical reads. If there are no RELEASE_APPROVED/non-published candidates that survive those gates, execution short-circuits directly to `WU103 Blocked Result`.

If at least one candidate survives preflight, the workflow continues to the existing shadow + canonical reads and the full hardened publisher decision.

## Preflight gates
- valid change ID / queue provenance / candidate key;
- duplicate active candidate key;
- human review approval;
- regression PASS;
- release approval;
- PII review;
- STAGING-only environment;
- privacy flags;
- regression payload hash binding;
- regression evidence hash;
- minimum two regression case IDs;
- source type/reference;
- non-empty language scope;
- valid ADD/UPDATE type;
- known target family;
- PACKAGES/POLICIES business-truth approval/source gate.

## Safety
- no new write node;
- no Production target;
- no self-approval;
- full publisher remains authoritative for payload validation, ID collision, stale-base, versioning, and retry/recovery;
- mixed batches still proceed to full validation when any candidate survives preflight;
- all-write behavior remains fail-closed.
