# CR-103-01 — Candidate Payload Storage

Status: ACCEPTED FOR IMPLEMENTATION REVIEW
Parent: WU-103
Issue: #30
PR: #32

## Problem
The frozen WU-103 change ledger includes `candidate_payload_sha256` but no field containing the actual curated knowledge payload. That makes the human review, regression, and publish stages non-executable.

## Correction
Add `candidate_payload_json` to the WU-103 change ledger contract and STAGING ledger tab.

Rules:
- the field contains curated/sanitized knowledge JSON only;
- it MUST NOT contain or automatically copy the WU-102 raw/redacted customer question;
- it must parse to an object accepted by the exact target-family adapter allowlist;
- canonical parsed JSON is the source for `candidate_payload_sha256`;
- any content edit changes the payload hash and invalidates earlier regression evidence;
- spreadsheet/formula injection escaping is applied only at the Sheets adapter boundary and is not part of the canonical hash;
- no Production KB target or customer-facing runtime is changed by this correction.

## Governance
This is a technical implementation correction discovered before WU-103 n8n implementation. It is not a separate owner approval or lock. It remains subject to WU-103 review, tests, final owner approval, and lock.
