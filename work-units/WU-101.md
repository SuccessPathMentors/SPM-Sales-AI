# WU-101 — Conversation Analytics

Status: SPEC_FROZEN — READY_FOR_IMPLEMENTATION
Version: 1.0
Issue: #12

## Objective
Capture one privacy-minimized, deterministic analytics event per completed customer turn so Phase 2 optimization can be driven by real traffic without changing the current customer-facing answer or existing business truth gates.

## Authoritative requirement
The approved Phase 2 backlog defines WU-101 as Conversation Analytics with these required signals: intent, secondary intent, confidence, language, session outcome, source gate, fallback use, clarification use, human-request signal, lead-conversion outcome, and safe telemetry. Analytics must not expose secrets or unnecessary PII and must not change customer-facing behavior.

## Freeze review decision
One material privacy finding was identified and resolved before freeze: RC4.3.3 accepts `input.correlation_id` when supplied, so `correlation_id` is not guaranteed to be internally generated. WU-101 therefore MUST NOT persist `correlation_id` or derive its analytics session key from it.

Frozen identifier design:
- `event_id` is generated internally for each analytics event.
- `analytics_session_key` is generated internally on the first Redis-backed turn and persisted in `sales_state.analytics.session_key`.
- `analytics_session_key` must never be derived from raw session ID, correlation ID, phone, email, names, contact fields, message content, or another customer-controlled field.
- `turn_index` is stored in `sales_state.analytics.turn_index` and increments exactly once per customer turn.

## Deterministic signal mapping
- `primary_intent` ← `classification.spm_intent`
- `secondary_intent` ← `classification.secondary_spm_intent`
- `confidence` ← validated `classification.confidence`
- `language` ← validated classifier language, otherwise safe language hint, otherwise `unknown`
- `journey_stage` ← `journey_decision.stage`
- `source_gate` ← `source_gate_result.gate` or `source_gate_decision.gate`
- `classifier_route` ← existing classifier route
- `clarification_used` ← existing clarification flag/route
- `fallback_used` ← existing fallback route
- `human_requested` ← existing human-handoff/support request signal only; it does not imply handoff execution succeeded
- `lead_outcome` ← verified WU95 state/write evidence only: `none|pending|created|updated|failed`
- `lead_id_present` ← boolean only; actual lead ID is not persisted
- `opt_out` ← existing nurture opt-out state
- `action_status`, `degraded`, `recovery_mode`, `duration_ms`, `error_codes` ← existing runtime/WU97 evidence

No second LLM classification or re-inference is allowed for analytics.

## Persistence decision
WU-101 V1 uses a dedicated `CONVERSATION_ANALYTICS` tab in the existing SPM runtime workbook. This is operational analytics data and must never be loaded into the Sales Agent prompt or treated as a knowledge source.

No raw question/message column is permitted in WU-101. Question capture/redaction belongs to WU-102.

## Customer-path isolation
Analytics is secondary observability and must be fail-open:
- analytics failure must not alter the answer;
- analytics failure must not alter lead truth;
- analytics must not determine booking/handoff/payment truth;
- analytics failure must not block the chat response;
- analytics errors must be observable with analytics-specific evidence;
- analytics retries must never repeat business writes.
